# 鼠标响应与启动闪退排查 · 2026-10-06

适用公开版本：alpha.7.1.6。本轮在源码中做了两处鼠标热路径优化，尚未打包、安装或发布。没有取得反馈电脑的启动日志，也未在该电脑复现，因此不能把以下候选原因当作已确认根因。

## 鼠标经过桌宠附近变慢

项目没有调用 Windows 鼠标速度/DPI 修改接口，也没有通过设置系统光标位置限制鼠标移动。当前输入采用 Electron `setIgnoreMouseEvents(..., {forward:true})`，同时每 60 毫秒用真实光标位置补充命中判断。

已核对所用 Electron 41.10.7 的 [Windows 实现](https://github.com/electron/electron/blob/v41.10.7/shell/browser/native_window_views_win.cc)：转发会安装 `WH_MOUSE_LL` 钩子，光标位于透明窗口客户区时转发移动消息。客户区还包含菜单和气泡的透明预留区域，所以受影响范围可能比看到的人物大。多只宠物、高回报率鼠标、主进程负载或其他鼠标钩子都是需要实测的影响因素，不代表已确认其中某一项导致此次反馈。

Electron 上游的 [Windows 光标闪烁报告 #35414](https://github.com/electron/electron/issues/35414)涉及同类转发路径，但光标形状闪烁与鼠标实际移动变慢不是同一结论。

本轮确认并优化：

- 主进程统一穿透入口对相同状态去重，避免渲染器与轮询先后发出相同状态时重复调用原生窗口 API。
- 气泡没有显示或不可选择时，鼠标移动处理不再读取气泡布局矩形；可选择气泡显示时仍正常测量。

定向验证通过：2000 条重复输入消息只在实际状态改变时调用原生 API；1000 次隐藏气泡鼠标移动不再读取气泡矩形；可见气泡命中、角色命中与透明区穿透、菜单开关/尺寸几何保持及沙箱开启均通过。此验证没有测量反馈者的物理鼠标延迟，也不能证明已经解决其主观卡顿。

若仍能复现，下一步在受影响电脑对比关闭转发钩子、保留主进程命中检测的候选版，并检查快速点击、拖动松手、气泡选择和菜单交互。不能直接删掉转发却不验证交互；现有 60ms 兜底频率也不能直接视为适合承担全部输入的最终方案。

## 只有加 --no-sandbox 才能启动

[Electron 沙箱文档](https://github.com/electron/electron/blob/v41.10.7/docs/tutorial/sandbox.md#disabling-chromiums-sandbox-testing-only)说明，此参数会关闭所有进程的 Chromium 沙箱，包含辅助进程；并非只改变桌宠的某个窗口。能因此启动是沙箱相关兼容性或权限问题的线索，不能据此断定必须永久关闭沙箱。

项目的宠物、控制台、托盘菜单开启 `sandbox:true`、`contextIsolation:true` 并关闭 `nodeIntegration`。主程序已经调用 `app.disableHardwareAcceleration()`，所以“再关闭硬件加速”不是新的排查变量；关闭硬件加速也不表示绝不会创建 GPU/图形辅助进程。

需要区分安装目录/用户数据权限、系统或安全软件对子进程的限制、Electron/Chromium 与图形环境的兼容问题，以及普通 JavaScript 初始化错误。另需确认是安装后的应用闪退，而非安装程序退出，或第二次启动时因单实例机制退出新进程。

目前的业务错误日志不足以覆盖原生进程早期失败；没有错误日志不等于没有崩溃。取得日志前不应自动添加 `--no-sandbox`、改成 `sandbox:false`、自动重置目录 ACL 或要求关闭安全软件。

## 请反馈者提供的最小信息

1. Windows 版本、桌宠版本、安装目录，以及启动的是安装后的 `pet-with-you.exe` 还是 `x64-setup.exe`。
2. 鼠标问题是箭头本身移动迟滞，还是点击/拖动响应迟滞；退出桌宠后是否恢复、当前几只宠物、是否只在人物或其周围区域发生。
3. 闪退后在 Windows 搜索“查看可靠性历史记录”，找到桌宠失败事件，打开技术详细信息，提供故障模块名、异常代码、故障时间。若没有记录，应注明。
4. 如日志模块仍能使用，可导出安全错误日志；公开分享前遮住个人用户名/路径，不发送密钥、auth.json、完整设置或私人对话。

这些信息用于判断产品代码、运行环境和电脑配置各自的影响，不能因为维护者机器能运行，就把问题归咎于使用者。
